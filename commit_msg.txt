refactor: wrap PyTorch nn.Module calls to eliminate Any propagation

PyTorch's built-in nn.Module subclasses (nn.Linear, nn.Embedding,
nn.LayerNorm, nn.Sequential, nn.ModuleList) declare __call__ with
return type Any. Under basedpyright's reportAny rule every call-site
that binds the result inherits that Any, silently defeating the type
checker for the rest of the expression chain. No amount of annotation
at the call site can fix it — the poison comes from the stub.

Introduce five thin typed wrappers in layers.py:

  TypedLinear      — nn.Linear with a jaxtyped __call__
  TypedEmbedding   — nn.Embedding with a jaxtyped __call__
  LayerNorm        — nn.LayerNorm with a jaxtyped __call__
  TypedSequential  — nn.Sequential with a jaxtyped __call__
  TypedModuleList  — nn.ModuleList with typed __iter__ / __getitem__
                     via Generic[TypedModule]

Each wrapper adds only a one-line __call__ override; it delegates to
self.forward(), which is already annotated. The wrappers carry no
logic of their own — they exist purely to propagate concrete types to
callers.

Propagate these wrappers throughout every architecture module (atom
transformers, main trunk, node/pair update, pairformer stack, template
embedder). Replace bare nn.* instantiations with the typed equivalents,
add explicit instance-variable annotations on every attribute that was
previously inferred, and decorate forward() and __call__() with
@override to satisfy reportImplicitOverride.

Move scatter_mean from main_trunk.py to atom_transformers.py, which is
where it is defined and consumed. Update test_main_trunk.py and
test_atom_transformers.py accordingly so the tests live next to the
code they cover.

Tighten the helper layer (bucketed_sampler, cluster_index, data) with
explicit instance-variable types and cast() calls to resolve opaque
numpy-indexing return types without suppressing any checks.

Elevate basedpyright's typeCheckingMode from "strict" to "all" in
pyproject.toml. The "all" mode activates every available check,
including reportAny and the other basedpyright-specific rules that
"strict" leaves disabled. The typed wrappers introduced here were the
last blocker preventing this upgrade; the codebase now passes cleanly
under the stricter setting.
