chore: enforce PLR2004 magic-value comparison checks

Previously PLR2004 was listed in ruff's `ignore` array on the grounds
that magic numbers are common in ML code. That blanket waiver was too
broad: it silenced legitimate style issues alongside the genuinely
necessary numeric literals (e.g. normalisation constants, fixed
mathematical coefficients).

Remove the waiver by commenting out the entry. Ruff will now flag
comparisons against unnamed literal values, encouraging named constants
where the number's meaning is non-obvious. The existing PLR2004-exempt
numeric literals that are truly self-evident (or already documented via
variable names and jaxtyping annotations) should pass without change;
any that do surface are worth naming explicitly.

The basedpyright config already carries an equivalent note at line 176
acknowledging the prior waiver; that comment remains as documentation
of the historical reasoning.
