refactor: replace cluster sharding with global FFD planning, fix decoder bug

The cluster-based sharding approach divided proteins into equal-width
length bins before packing them into shard tars. This introduced
arbitrary bin boundaries that degraded padding efficiency at cluster
edges and produced a single monolithic ShardBatchPlan shared across
all DataLoader workers, forcing each worker to re-derive the same
global ordering rather than owning a disjoint shard slice.

Replace the entire batching stack with worker-aware FFD planning:

Data pipeline (helpers/data.py)
- Remove ClusterMetadataEntry, ShardBatchPlan, and the two-pass
  compute_clusters / compute_shards methods. Replace with a single
  build_sorted_shards pass that globally sorts proteins descending
  by seq_len and slices them into sequential shard tars — no bins,
  no arbitrary boundaries.
- Introduce FFDWorkerPlan and FFDBatchPlan as Pydantic models instead
  of plain dataclasses. Each DataLoader worker now owns a disjoint
  shard slice so FFD batch construction is fully local.
- Add num_workers and noise_magnitude to ShardBudgetParameters. The
  uniform noise half-width randomises sort order across epochs to
  improve batch diversity without sacrificing mean padding efficiency.
- Drop n_clusters from ShardMetadata; it was only meaningful under
  the old cluster scheme.

Config (train/train_config.py, train/run_config.json)
- Replace n_clusters and n_proteins_in_shard with n_shards in
  TrainLoaderConfig, matching what the FFD pipeline actually needs.
- Add InsufficientShardsError and a Pydantic model_validator that
  rejects configs where num_workers > n_shards at construction time
  rather than producing a confusing WebDataset error during iteration.

Featurizer (helpers/featurize.py)
- Thread window_size through featurize_single_item so the sparse
  atom-pair window is driven by model_params.window_size rather than
  the module-level WINDOW_SIZE constant, removing a hidden coupling
  between the featurizer and the architecture module.

Bug fixes
- AtomAttentionDecoder.proj_z projected from c_res instead of c_pair,
  causing a dimension mismatch when c_res != c_pair. Fix the input
  dimension to c_pair as the layer comment already stated.
- StructlogConfig.write_event_dict called json.dumps without
  default=str, raising TypeError whenever an event dict contained a
  Path or other non-serialisable value. Pass default=str to coerce
  those values gracefully.
- evaluate() and train() annotated their DataLoader as
  DataLoader[Protein] instead of DataLoader[list[Protein]], hiding
  the per-batch list wrapping from the type checker.

Tests
- Update all fixtures to drop n_clusters, supply n_shards, and use
  the new factory pattern for ProteinShardDataset construction.
- Remove test_train_config.py (superseded by the inline validator
  tests on TrainLoaderConfig).
